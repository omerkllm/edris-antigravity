## Summary

Build an AI-powered web application that scans a batch of 5–15 student opportunity emails, classifies them, extracts structured fields, scores each against a student profile using a deterministic 0–100 ranking engine, and returns a ranked priority list with evidence strings and action checklists. The system uses exactly 3 AI API calls regardless of email count (batch classify → batch extract → batch checklists), with deterministic fallbacks for every AI failure path.

**Tech stack**: FastAPI (Python 3.11) + Gemini 2.0 Flash (free tier) / Ollama fallback + React 18 + Vite 5 (TypeScript).

## Constitution Check

The project constitution is established at `.specify/memory/constitution.md` (v1.0.0) and is **non-negotiable**. This plan aligns with Principles I–VIII as follows:

- ✅ **I. Algorithmic Efficiency**: O(1) dedup via hash set; single O(n log n) sort for ranking; substring checks for URL validation.
- ✅ **II. Code Structure & Modularity**: Pipeline is split into per-concern modules (`ingestion`, `classifier`, `extractor`, `scoring`, `checklist`, `ai_client`). Route handlers orchestrate; they do not inline business logic.
- ✅ **III. Phase-Gated Delivery**: Implementation phases are defined in `tasks.md` and require explicit user “proceed” at each checkpoint.
- ✅ **IV. Context Continuity**: Each substantive turn is appended to `context/session_log.md` (append-only).
- ✅ **V. No Faulty Code**: No stubs in deliverables; AI JSON parsing is guarded with explicit fallbacks.
- ✅ **VI. Security/Validation/Rate Limiting**: Pydantic validation at API boundary; file type/size checks; per-IP sliding window limiter; generic 500 errors; never log secrets.
- ✅ **VII. Simplicity First**: Stateless per-request; no DB/auth; minimal dependencies.
- ✅ **VIII. Minimal UI Priority**: Plain HTML inputs and basic CSS only; no UI libraries; only functional loading affordances (spinner/step text) if needed.

No constitution deviations are currently planned.

## Flow Architecture (5 Flows, 3 API Calls)

```
POST /api/analyze
       │
       ▼
┌─────────────────────────────────────────────────────────────┐
│ Flow 1: INGESTION (services/ingestion.py)                   │
│  • Split paste on ---EMAIL--- or read .eml/.txt files       │
│  • Build RawEmail[] (id, subject, sender, body, raw_text)   │
│  • Filter: < 30 chars → FilteredOut["too short"]            │
│  • Deduplicate by SHA-256 hash of first 200 body chars      │
│  • Truncate to first MAX_EMAILS (15)                        │
│  • Truncate each body to MAX_BODY_CHARS (3000)              │
└─────────────────────────────────────────────────────────────┘
       │  RawEmail[]
       ▼
┌─────────────────────────────────────────────────────────────┐
│ Flow 2: CLASSIFICATION (services/classifier.py)             │
│  AI CALL #1 — Single batch prompt for all emails            │
│  • On JSON parse failure → all emails = is_opportunity:true │
│  • Split into: opportunities[] + filtered_out[]             │
│  • Mark confidence < 0.6 → classification_uncertain=true   │
└─────────────────────────────────────────────────────────────┘
       │  opportunities: RawEmail[] (with ClassificationResult)
       ▼
┌─────────────────────────────────────────────────────────────┐
│ Flow 3: EXTRACTION (services/extractor.py)                  │
│  AI CALL #2 — Single batch prompt for opportunities only    │
│  • Validate URLs: not in raw_text → discard (null)          │
│  • Convert CGPA % → 4.0 scale                               │
│  • On per-email parse failure → null OpportunityObject      │
│  • Output: OpportunityObject[] (one per opportunity email)  │
└─────────────────────────────────────────────────────────────┘
       │  OpportunityObject[]
       ▼
┌─────────────────────────────────────────────────────────────┐
│ Flow 4: SCORING ENGINE (services/scoring.py)  ← ZERO AI    │
│  • For each opp: compute 4 dimensions (0-40, 0-30, 0-20, 0-10)│
│  • Assign urgency badge (RED/YELLOW/GREEN/ROLLING/etc.)     │
│  • Generate deterministic evidence strings                  │
│  • Flag is_ineligible (CGPA hard fail)                      │
│  • Sort: eligible by score desc, ineligible last, expired   │
│           last, tie-break by days_left asc then title alpha │
│  • Output: ScoredOpportunity[] (ranked)                     │
└─────────────────────────────────────────────────────────────┘
       │  ScoredOpportunity[] (ranked)
       ▼
┌─────────────────────────────────────────────────────────────┐
│ Flow 5: CHECKLIST (services/checklist.py)                   │
│  AI CALL #3 — Single batch prompt for all ranked opps       │
│  • On failure → fallback_checklist() from structured fields │
│  • Attach checklist[] to each ScoredOpportunity             │
│  • Output: RankedOutput[] (final)                           │
└─────────────────────────────────────────────────────────────┘
       │  FinalResponse JSON
       ▼
    React UI
```

## AI Client Design (`services/ai_client.py`)

```python
class AIClient:
    def __init__(self, provider: str, gemini_key: str, ollama_url: str, ollama_model: str)
    
    async def call(self, system_prompt: str, user_prompt: str) -> str:
        """
        Single method used by classifier, extractor, and checklist generator.
        Routes to Gemini or Ollama based on LLM_PROVIDER env var.
        Retries once on JSON parse failure before raising.
        """
```

- **Gemini path**: Uses `google.genai.GenerativeModel.generate_content()` with `response_mime_type="application/json"`. Temperature = 0.1.
- **Ollama path**: HTTP POST to `{OLLAMA_BASE_URL}/api/chat` with `format: "json"`.
- **Retry**: On first JSON parse failure, retry once with added instruction `"Respond ONLY with valid JSON, no other text."`.

## Frontend State Machine

```
App state: "input" | "loading" | "results" | "error"

input    → [Submit] → loading (POST /api/analyze)
input    → [Load Demo] → loading (GET /api/demo)
loading  → [200 OK] → results
loading  → [4xx/5xx] → error (with retry button)
results  → [Analyze Again] → input (reset state)
error    → [Try Again] → input (reset state)
```

The loading state shows sequential step labels so the user knows the system is working:
1. "Parsing emails..." (instant)
2. "Classifying opportunities..." (AI Call #1)
3. "Extracting details..." (AI Call #2)
4. "Ranking by your profile..." (deterministic)
5. "Generating action plan..." (AI Call #3)

Note: Steps 2–5 happen server-side in one HTTP call; the frontend simulates progress with a timed animation.

## Design Decisions Summary

| Decision | Choice | Reason |
|----------|--------|--------|
| Primary LLM | Gemini 2.0 Flash | Free tier, JSON mode, fast, large context |
| Local fallback | Ollama llama3.2:3b | True offline capability, toggled by env var |
| Backend | FastAPI + Uvicorn | Native async, auto docs, Pydantic validation |
| Frontend | React 18 + Vite 5 + TypeScript | User requested React; Vite = fast dev; TS catches schema bugs |
| Storage | None | Stateless per-request; no persistence needed |
| Demo mode | Pre-computed JSON fixture | Immune to rate limits and internet outages |
| AI call budget | Hard 3-call limit | Deterministic cost; prevents runaway API usage |
| URL validation | Check verbatim in raw_text | Prevents hallucinated links reaching students |
| Scoring | Pure Python, zero AI | 100% deterministic, unit-testable, auditable |
